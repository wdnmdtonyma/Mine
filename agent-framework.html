先落盘再处理。页面关了、进程崩了，才恢复得回来。对你来说只是「我说了一句」；对机器来说，这是一轮任务的起点，后面会套着好几次问模型。

钉死一句：模型两次调用之间什么都不记得。你看见它忙了一阵，是这台循环在转，不是它脑子里一直挂着这件事。

内核在固定时刻对外开口，让别人不改源码也能插一脚。用户刚提交，是第一处。

这一脚能干什么

  • 什么都不做。没配 Hook，就当这层不存在。

边界

  • Hook 能往上下文里塞字，不等于能绕过后面的权限门。
  • 会变的信息（时间、目录）从这里进，不要烤进 system 最前面——那会把缓存每轮打碎。

提示词是常驻真理。Hook 是「这一刻临时贴一张纸条」。两件事不要混在一个抽屉里。

发给模型的不是一段话，是一只按顺序装好的箱子。身份、项目约定、Skill 目录、工具说明书、你刚说的话，都在这里排队。

看那条色带

你那句话只占很小一块。大部分是铁律和工具说明书。所以「效果不好就改提示词」常常改错层——真正漏的，可能是项目说明书没写清，或工具太多把选择淹没了。

三根杠杆落在哪

  • Prompt → system 那一行。改默认怎么想、听谁的。
  • Skill → 目录卡片 + 那个叫 Skill 的工具。改某类事怎么一步步干。
  • MCP → 延迟工具那一行。给模型新的手，去碰工单、表格、发消息。

分享口播

停在这只箱子上多讲一会儿。后面问模型、跑工具，都是在消化这只箱子。箱子装错了，模型再聪明也是按错的材料想。

回答三个问题：我是谁、我该怎么做事、碰到矛盾听谁的。理想情况下一个会话几乎不变，所以该被缓存。

听谁的

  • 安全铁律。谁都覆盖不了。
  • 系统政策。怎么写代码、怎么用工具。
  • 项目文件、Skill 正文。更低。不准反客为主。

边界

  • 当前时间、模式开关，不要放进这一段的最前面。
  • 不是越长越聪明。铁律短而硬，偏好放到项目说明书。

分享口播

这就是大家说的 Prompt。改它，是在改常驻真理。一句偏好、一套作业步骤、一只外部的手，都不该塞进这里。

模型要知道「这里」是哪。读文件、找 AGENTS.md、发现 Skill，都从工作目录长出来。

它会带着什么

路径、是不是 git 仓库、有时还有平台信息。Codex 更省：第一轮给全量，之后只发「相对上次变了什么」。会变，所以不进铁律前缀。

分享口播

运营配的项目说明书，不是凭空出现的。是机器看着你现在站在哪个目录，把那份 md 读进来。目录错了，规矩就装错了。

这个仓库的说明书。Claude 叫 CLAUDE.md，Codex / 很多后来者叫 AGENTS.md。从当前目录往上找，读进来，塞进箱子。

写什么才有用

  • 怎么跑起来。安装、测试、发版。
  • 数字口径。指标怎么算，禁止编造。
  • 红线。生产配置、密钥、不能自动提交。

边界

  • 低于系统指令。位置上压，文字里也最好写明。
  • 要有长度上限。写成长篇「团队规范」，会把真正重要的挤糊。

分享口播

这是运营和产品最该贡献的一张卡片。不是写「注意质量」，是写「改活动配置前先读口径表、发版必须跑哪条检查」。

你不可能把每个能力的完整说明书常驻。只让名字加一句「什么时候用我」常驻。正文等模型决定用了，再经 Skill 这个工具取回来。

命门是描述

写成「一个很有用的工具」等于没写。写成「用户要发版检查、对账、按品牌改文案时用我」才找得到。运营能贡献的，恰好是这张卡片。

和 Prompt 的差别

Prompt 是每轮都在的真理。Skill 是某一类事的作业包。一句偏好不要做成 Skill；一套可复用步骤，不要写成 Prompt。

分享口播

点这一行时说：模型现在只看见 6 张目录卡片，看不见周报该怎么写。要用，它得再调下面那个叫 Skill 的工具。

读、改、跑命令。带完整说明书。清单顺序要稳定，顺序一抖，缓存就废。

发给模型的只有说明书

名字、描述、参数长什么样。是不是只读、能不能并行、要不要批准，是拿到真实参数之后才算的。永远不让模型自己声明「我这个调用是安全的」。

分享口播

核心工具要少而清。描述就是模型的搜索词。叫含糊的名字，等于不存在。

箱子里除了读、改、跑，还常驻着一个专门用来打开作业包的工具。模型判断「这事儿该按周报那套干」，就调它，把那份正文取回来。

找，然后打开

目录卡片让它知道有哪些作业；这个工具让它真的把某一份打开。有的实现还会先「找一找」再「打开」。对听众只要记住：Skill 不是一句提示词，是「目录 + 一个能把正文取回来的手」。

边界

  • 正文较低信任，可能来自第三方。准用哪些工具，要绑在技能上。
  • 可以选开一个子任务跑，避免大段作业说明污染主对话。

分享口播

这次重构未必用到它，但它已经坐在箱子里。任务一旦变成「按我们的口径写周报」，模型会先调这个，而不是自己编步骤。

接了 MCP 之后，工具轻松上百。每轮把全部说明书塞进脑子，模型和账单会一起崩。所以长尾先只露名字。要用，先调这个搜索工具，把说明书召回来。

自举

这个找工具的工具自己必须永不延迟。否则模型没有入口，后面 41 个名字等于隐形。Claude 对外部工具一律延迟；只有被点名的那一个，付过说明书的字数账。

和 Skill 是一对

  • Skill。找的是作业说明（怎么干）。
  • ToolSearch。找的是手（碰哪个外部系统）。

分享口播

这就是「召回」的人话：不是检索一篇文档，而是把某个工具从「我听说过」变成「我能调用」。先接一堆 MCP 再写百科，是最常见的失败。

MCP 给模型新手：工单、表格、内部接口。它解决「手够不着」，不解决「不懂怎么做」。

该接 / 不该接

  • 该。要让 Agent 动手碰外部系统。
  • 不该。只是想让步骤变稳——那是 Skill 和项目说明书。

代价

工具数暴涨。必须配套 ToolSearch。发送、改生产，必须问人。远端来源不准直接跑命令行。

分享口播

最划算，不等于排得最早。先把「听谁的」摆对，再把高频作业收成 Skill，最后才接 MCP，并打开延迟加载。

用户说的、模型说的、工具结果，按时间追加。只在末尾加，前面逐字不变，缓存才滚得动。

卫生

  • 有调用必须有结果。中断了就补一条「已中止」。
  • 一条测试日志可以把窗口撑爆，输出要有上限。
  • 压缩是付费事件：前面换成摘要，会忘，还要重建缓存。

分享口播

第 1 次问模型时，历史几乎就是你那句话。第 2 次，多了文件内容。所以它不是「想一下就答完」，是一轮任务套着多次询问。

箱子已经装好。真正发出去前，还可以再注入高度易变的话：现在是规划还是动手、还剩几个待办。

为什么不进铁律

这些每轮都可能变。放进 system 最前面，缓存每轮作废，又贵又慢。正确做法是跟最新的用户消息走，每轮新鲜贴一份，并标明：这些来自系统，但不是最高权威。

分享口播

Hook 出现在好几个时刻：开口时、发出去前、动手前、想收工时。同一类机制，卡在循环的不同缝上。发起这一刻，最常见的用途就是贴提醒，而不是改铁律。

打开模型的流，边收边解析。吐出来的可能是对人说的字，也可能是「请帮我调某个工具」。

粒度

  • 一轮任务。从你开口到交还控制权。就是上面那句重构。
  • 一次采样。对模型的一次调用。本例会有三次。

分享口播

不要说「模型想了一下」。说「第 1 次问它」。它说先读文件，循环必须把文件喂回去，再问第 2 次，它才能改。

它对人说「我先看一下」，同时在回复里夹了一个工具调用。成熟实现看实际收到的工具块，不看「我说完了」那个标签。

这次为什么没用 Skill / ToolSearch

读本地文件是常驻工具，说明书已经在箱子里。重构还不需要外部系统和作业包。那两个找东西的工具在待命——任务一变成发周报，就会被用上。

分享口播

模型只会输出文字。能读到 utils.ts，全靠运行时按约定去执行，再把 412 行写成一条结果。

模型点了工具，还不能直接跑。先过 Hook，再过权限门。

权力上限

  • 可以拦住一次危险调用。
  • 可以改写入参。
  • 不能把权限放宽到突破拒绝名单。

分享口播

读文件通常自动过。发消息、改生产、删数据，会停在「等你点」。这一轮任务看起来像卡住了，其实是门在工作。

真的去读盘。成功、失败，都变成一条工具消息，追加到箱子末尾。

失败是主通道

找不到路径、文件太大被截断，都应该写成原因喂回去。「出错了」不如「文件不存在，是否想读 src/utils.ts」。后者模型能改。

分享口播

用户看到失败气泡，先别当成事故。问：原因写得够不够它改下一次？不够，是产品问题。

模型不记事。第 2 次问，要把第 1 次的对话和刚刚读到的 412 行重新带上。

什么尽量别动

铁律、工具清单顺序、已经说过的话。只在末尾追加。改写中段会把缓存打碎，同一段身份指令按全价重算。

分享口播

这就是为什么「在系统提示最前面加当前时间」是灾难：前缀每轮都变，缓存全废。

续采：有工具结果要消化，就必须再问一次。用户感觉仍是同一件事在往下做。

分享口播

任务结束不等于模型这一次说完了。第 1 次说完只结束采样。整轮任务还在继续。

看见内容之后，才发起修改。精确替换：旧文字 → 新文字。必须先读过、文件没被别人改过、匹配必须唯一。

纠正回路

匹配不上就大声失败，绝不静默写错地方。用户看到「找不到这段文字」，往往是守卫在工作：模型拿着过期视图去改，系统拒绝，让它重新读。

分享口播

现场若能演示一次失败再改成功，听众会记住纠正回路，而不是记住循环的名字。

改文件走本地执行。可见、可派发，真要执行还要过门。拒绝优先。

三种门

  • 允许。低风险，自动过。
  • 问人。这一轮停在等待上。
  • 拒绝。写成原因喂回模型，换一条路。不是任务失败。

分享口播

「请小心」写在提示词里，挡不住。真正挡得住的，是这一道门。

工具结果回来了，再问一次。它决定：还要不要动手，或开始对人总结。

分享口播

本例三次采样：读、改、说。复杂任务可以是十几次。预算要挂对层：字数花在每一次询问上，工具次数挂在这一轮任务上。

对人说话，并且没有新的工具调用。是不是真能停，还不是它说了算。

分享口播

上面聊天框里那句「改完了」，到这一步才出现。前面十几行，用户平时看不见。今天把控制台打开，就是让大家看见这些。

模型说做完了。规则仍可强制续跑：测试没过、预览没出、还没干到预算的九成。

几道闸

  • 模型行为。这轮是不是真的点了工具。看行为，不看标签。
  • 规则否决。本层。
  • 空转。连续续跑却几乎没产出就停。
  • 硬上限。前面全失灵时的保险丝。

分享口播

「Agent 偷懒」和「Agent 死循环」往往不是模型性格，是这组闸没调好。交付前必须跑通测试，不要写进提示词求它自觉。

一轮任务结束。效果几乎全在这台循环上：箱子怎么装、工具怎么召回、失败怎么喂回去、什么时候停。

优化时先问卡在哪

  • 答非所问 → 动项目说明书 / 铁律。
  • 步骤乱 → 写 Skill，描述写清何时用。
  • 手够不着 → 接 MCP，并打开延迟加载。
  • 一接外部就胡来 → 动权限门，不要在提示词里写请小心。

分享口播

收在这句：Prompt、Skill、MCP 不在同一格，不能互相替代。先摆对听谁的，再收作业包，最后才给新手。

重构走的是读和改。发周报走的是「按我们的步骤干」。模型先调 Skill，把周报作业包的正文取进对话。

作业包里有什么

拉哪些数、口径以谁为准、套哪张模板、先预览再发。这些不要写进 system——那是某一类事的流程，不是所有任务的铁律。
